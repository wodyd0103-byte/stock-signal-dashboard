- 화면 구조와 디렉터리, 코드를 고칠 때 볼 것 → [frontend/README.md](../frontend/README.md)

여기 적힌 판단은 대부분 그 자리의 코드 주석에도 있습니다. 이 문서의 몫은 **파일 하나만
봐서는 안 보이는 것** — 결정끼리의 관계, 대안을 버린 이유, 일부러 하지 않은 것 — 입니다.

## 1. 배포가 앱과 갈라져 있다

백엔드는 `pykrx`/`yfinance`로 외부 시세를 긁고 SQLite에 씁니다. 정적 호스팅에 올릴 수
없습니다. 그렇다고 프론트만 올리면 카드마다 "백엔드에 연결할 수 없습니다"만 보입니다.

그래서 **실제 백엔드가 돌려준 응답을 `frontend/demo-data/`에 받아두고**,
[`scripts/build-demo-api.mjs`](../frontend/scripts/build-demo-api.mjs)가 그것을
백엔드와 **같은 경로 모양**의 정적 파일로 펼칩니다.

```
demo-data/analysis.json  →  public/api/demo/stocks/005930/analysis
```

확장자를 붙이지 않는 이유는 앱이 부르는 경로 그대로여야 하기 때문입니다.
`fetch().json()`은 Content-Type을 보지 않으므로 확장자 없이도 파싱됩니다.

**같은 파일을 테스트도 봅니다.** [`tests/mock-api.ts`](../frontend/tests/mock-api.ts)가
Playwright 라우트를 가로채 `demo-data/`를 돌려줍니다. 둘이 갈라지면 *테스트가 통과한
화면*과 *사람들이 링크로 보는 화면*이 달라집니다. 픽스처를 `tests/` 밑에 두지 않고
`demo-data/`로 올린 것도 같은 이유입니다 — 프로덕션 코드가 테스트 디렉터리를 읽으면
안 되니까요.

값이 고정이라는 사실은 숨기지 않습니다. 닫을 수 없는 상단 배너, "실시간 데이터"가 아닌
"미리 받아둔 응답"이라는 출처 문구, 쓰기 요청에 대한 405가 그 장치입니다.

> `portfolio.json`과 `watchlist.json`만은 캡처본이 아니라 **손으로 쓴 예시**입니다.
> 이 둘은 "누가 무엇을 들고 있는가"라서, 캡처를 그대로 두면 공개 저장소에 실제
> 보유·관심 종목이 남습니다.

## 2. 데이터 조회는 실패를 감추지 않는다

[`data_provider.py`](../backend/app/services/data_provider.py)는 티커 모양으로 시장을
판별하고, 한국 종목이면 `pykrx` → 실패 시 `FinanceDataReader` 순으로 시도합니다.
어느 쪽이 얼마나 실패했는지는 `providers_tried`에 그대로 담겨 응답까지 올라갑니다.

**샘플 폴백은 기본값이 꺼져 있습니다**(`ALLOW_SAMPLE_FALLBACK=false`). 켜져 있으면
외부 조회가 실패했을 때 그럴듯한 합성 데이터가 조용히 화면에 뜹니다. 투자 참고용
숫자를 보여주는 앱에서 그건 오류보다 나쁩니다. 켤 때조차 `source="sample"`,
`is_sample=true`가 API와 화면에 드러납니다.

라우터는 이 실패를 두 갈래로 번역합니다 — 티커 형식이 틀렸으면 **400**(사용자 잘못),
제공자가 죽었으면 **502**(업스트림 잘못). 한 덩어리로 뭉뚱그리면 화면에서 "다시
입력해야 하는지, 기다려야 하는지"를 구분할 수 없습니다.

## 3. 프론트의 데이터 흐름은 훅 두 개로 좁혀져 있다

여덟 개 컴포넌트가 `data`/`loading`/`error` 3-state와 `try-catch-finally`를 복사해
쓰고 있었습니다. 그 복사본 **전부에 같은 버그**가 있었습니다 — 탭이나 기간을 빠르게
바꾸면 먼저 보낸 요청이 나중에 도착해 화면을 과거 값으로 되돌렸습니다.

[`useAsyncData`](../frontend/hooks/useAsyncData.ts)는 응답을 **요청 키에 저장하고
화면은 현재 키만 읽습니다.** 늦게 온 응답은 화면을 건드릴 수 없습니다 — 취소가 아니라
구조로 막은 것입니다. `loading`도 state가 아니라 "현재 키의 응답 없음"으로 계산되므로
이펙트 안 `setState`가 사라졌고, 그 결과 **프론트 전체에 `eslint-disable`이 0개**입니다.

클릭이 시작하는 요청(추가·삭제·계산)은 조회와 수명이 달라
[`useAsyncAction`](../frontend/hooks/useAsyncAction.ts)으로 분리했습니다.
조회는 [`hooks/queries.ts`](../frontend/hooks/queries.ts)가 이름으로 제공하므로
컴포넌트가 엔드포인트 파라미터를 들고 있지 않습니다.

## 4. 테스트는 세 층으로 나뉘고, 경계에 이유가 있다

| 층 | 도구 | 맡는 것 | 맡지 않는 것 |
| --- | --- | --- | --- |
| 순수 함수 | Vitest | 매칭·정렬 규칙, 화살표 인덱스 계산, 신호 색 경계 | DOM |
| 컴포넌트 | Vitest + RTL | 표시 규칙, 키보드 조작, 지연 로딩 | 레이아웃 |
| e2e | Playwright | 실제 레이아웃·요청 수·접근성 트리 | 위에서 되는 것 |

경계를 정하는 질문은 **"이건 여기서만 볼 수 있나"** 입니다.

- 가로 넘침은 브라우저에만 레이아웃 엔진이 있으니 e2e입니다. 숨은 탭은
  `display:none`이라 레이아웃이 없어서, 탭을 순회하지 않으면 1/3만 검사하게 됩니다.
- "아무 일도 일어나지 않는 것이 정상"인 동작은 e2e로 못 봅니다. 탭에서 위아래
  화살표를 눌러도 안 움직이는 규칙은 [`rovingFocus.ts`](../frontend/hooks/rovingFocus.ts)의
  단위 테스트만 덮습니다.
- 요청 횟수처럼 "화면에 안 보이는 계약"은 e2e에서 요청을 세서 확인합니다.

`vitest.config.mts`가 `*.test.*`만 수집하고 `tests/`를 통째로 제외하는 것도 이
분업 때문입니다. 확장자가 겹치면 Vitest가 Playwright 스펙을 집어 `test.describe`에서
터집니다.

## 5. 테스트를 믿을 수 있게 만드는 방법: 회귀 주입

**새 테스트는 반드시 회귀를 주입해 실패시켜 본 뒤에 남깁니다.** 머지된 커밋 13개가
그 결과를 담고 있습니다.

방법은 간단합니다. 소스에 옛 버그를 되돌려 넣고, **실패해야 할 테스트를 이름으로
지정해** 돌린 뒤, 원본을 복원합니다. 파일 전체를 돌리면 주입과 무관한 테스트가
먼저 깨져도 "잡혔다"로 보이므로 반드시 지목해서 돌립니다.

이 과정에서 실제로 드러난 것들:

- **테스트가 아무것도 보장하지 않던 경우.** `/analysis`는 매수 신호일 때만 추천을
  기록하는데 합성 랜덤워크로는 매수 신호가 안 나옵니다(전부 HOLD). 그래서 양쪽 분기
  테스트가 같은 빈 케이스였고, 24시간 중복방지를 통째로 지워도 통과했습니다.
- **느슨한 단언.** "에러 문자열에 `volume`이 있나"로 컬럼 검증을 확인했는데,
  검증을 지우면 나는 `KeyError: "['volume'] not in index"`에도 그 단어가 있었습니다.
- **테스트 쪽이 틀린 경우.** 색 대비를 직접 재는 검사가 문단 대신 아이콘을 집었고
  (둘 다 `text-warn`), 조상 배경 합성 순서가 뒤집혀 있었습니다. 둘 다 *진짜 미달인
  페이지를 멀쩡해 보이게* 만들던 버그입니다.

주입했는데 통과하면 셋 중 하나입니다 — 주입이 약하거나, 테스트가 비었거나,
지목한 테스트가 그 동작을 안 덮습니다.

## 6. 접근성은 게이트로 잠겨 있고, 도구의 사각지대를 손으로 메운다

[`tests/a11y.spec.ts`](../frontend/tests/a11y.spec.ts)가 `@axe-core/playwright`로
네 화면 × 두 테마를 훑고 **WCAG 2.1 AA 위반 0건**을 강제합니다. CI가 `tests/`
전체를 돌리므로 별도 워크플로 설정은 없습니다.

자동 검사만으로는 부족해서 직접 단언하는 것이 셋 있습니다.

1. **axe는 규칙 위반만 보고 "쓸 수 있는지"는 보지 않습니다.** 포커스 트랩, 닫을 때
   포커스 복귀, 화살표 순회는 손으로 씁니다.
2. **axe의 WCAG 규칙집합은 대화상자 이름을 요구하지 않습니다**(`aria-dialog-name`은
   `best-practice` 태그). `aria-labelledby`를 통째로 지워도 스캔이 통과했습니다.
3. **axe는 배경을 확신할 수 없으면 위반이 아니라 `incomplete`로 넘깁니다.** 반투명
   오버레이 위, 그라디언트, 차트 안이 그렇고 이 앱에만 100건이 넘습니다. 실제로
   색을 옛 값으로 되돌려도 대화상자 본문이 미달인 채 스캔이 통과했습니다. 그 자리는
   조상 배경을 직접 합성해 계산합니다.

스캔 전에 애니메이션을 끝내는 것도 필수입니다. 카드가 페이드인 하는 중에 재면 axe가
전환 도중의 색을 읽어 배경이 `#ffffff`가 아니라 `#f9fafb`로 잡힙니다. 기준선이 3배
부풀어 보였던 이유입니다(105 → 32).

## 7. 색 토큰은 테마와 역할로 두 번 갈린다

브랜드색이 원래 "양 테마 공통" 고정 hex였습니다. 흰 배경용으로 고른 빨강이 어두운
카드 위에 그대로 앉았고, 다크 모드가 라이트보다 나빴습니다(분석 화면 136 대 48).

지금은 CSS 변수로 **테마별**로 갈리고, 그 위에 **역할별**로 한 번 더 갈립니다.

```css
--c-up          /* 글씨 — 라이트에선 어둡게, 다크에선 밝게 */
--c-up-strong   /* 흰 글씨를 얹는 배경 — 양 테마 공통 */
```

한 값이 둘 다 할 수 없습니다. 흰 글씨를 받는 빨강은 어두워야 하고, 어두운 카드에서
읽히는 빨강은 밝아야 합니다. 라이트에서는 두 값이 거의 겹쳐서 예전 코드가 넘어갔던
것이고, 다크가 그 차이를 드러냈습니다.

같은 이유로 [`lib/sentimentColor.ts`](../frontend/lib/sentimentColor.ts)가
**계조와 가독성을 분리**합니다. 게이지 아크는 5단 계조(장식이라 AA 대상이 아님),
숫자와 칩은 3단 테마 토큰. 중간 단계의 연한 색은 계조로는 필요하지만 글씨로는
읽히지 않습니다.

텍스트 색에 알파를 걸지 않는 규칙도 여기서 나왔습니다. `text-warn/90`처럼 쓰면
색 자체가 AA를 지켜도 투명도가 대비를 그만큼 깎습니다. 흐릿함은 알파가 아니라
더 연한 토큰으로 표현합니다.

## 8. 일부러 하지 않은 것

- **TanStack Query** — 도입 명분이던 `eslint-disable` 3개는 훅 분리로 이미 사라졌습니다.
  진짜 필요해지는 시점은 서버 상태를 컴포넌트 간에 공유·무효화해야 할 때입니다(관심종목
  추가가 여러 화면에 즉시 반영되는 식). 지금은 `page.tsx`가 ref로 레일을 새로고침합니다.
  훅 인터페이스(`data`/`error`/`loading`/`refetch`)를 맞춰뒀으므로 교체는 국소적입니다.
- **색 대비 회귀 게이트를 조합 단위로 고정하기** — axe는 합성된 색을 보고하므로 토큰
  하나가 배경에 따라 여러 hex로 흩어집니다. 불투명도만 바뀌어도 깨지는 게이트는
  없느니만 못해서, 되는 척하지 않고 뺐습니다.
- **`next/font`로 폰트를 번들에 넣기** — 오래 "제대로 된 해법"으로 적어뒀다가, 실제 파일
  크기를 재보고 접었습니다. Pretendard의 dynamic subset은 92조각 약 3.2MB이고 통짜
  variable woff2는 2.0MB인데, `next/font/local`은 `unicode-range`를 표현할 수 없어
  조각을 쓰지 못합니다. 즉 next/font로 가면 **모든 방문자가 2.0MB를 한 번에 받습니다.**
  지금은 실제 쓰이는 조각 몇 개만 받습니다. 렌더를 막던 것은 폰트 파일이 아니라
  스타일시트였고, 그것만 [`app/fonts.css`](../frontend/app/fonts.css)로 내렸습니다.
- **실시간 주문 실행** — 이 앱은 분석 전용입니다. 매매는 외부 증권사 앱에서 하고,
  분석 결과는 CSV로 내보냅니다.

## 9. 알려진 구조적 빚

- **백엔드에 인증이 전혀 없습니다.** 로컬 전용이라 지금은 문제가 아니지만, 공개 IP에
  띄우면 누구나 보유 종목을 추가·삭제할 수 있습니다. 호스팅할 계획이 생기면 그게 1순위입니다.
- **폰트 파일은 여전히 외부 CDN(jsDelivr)에서 옵니다.** 렌더를 막던 스타일시트만 번들로
  내렸고(위 8번), woff2 조각은 그대로 바깥에서 받아옵니다. CDN이 죽으면 fallback 폰트로
  렌더됩니다. 자체 호스팅하려면 92조각 3.2MB를 저장소에 넣어야 합니다. **전송량으로는
  얻을 것이 없습니다** — 걷어낸 CDN 스타일시트가 12,493바이트(brotli)였고 그 자리에 들어간
  우리 CSS 청크가 13,057바이트(gzip)입니다. 남는 이득은 외부 오리진 하나를 지우는 것뿐입니다.
- **컴포넌트 단위 테스트가 표시 계층 전부를 덮지는 않습니다.** 스스로 계산하는 것들
  (`PriceTargetCard`, `ComparePanel`, `SupplyDemandCard`, `RiskCard`, `IndicatorTable`,
  `SignalCard`, `SignalHistoryPanel`, `FearGreedGauge`, `StockSearch`)은 덮었고, 백엔드
  값을 그대로 찍는 카드들은 비어 있습니다. 그쪽은 테스트가 렌더러를 다시 적는 꼴이라
  회귀를 잡지 못해서, 계산이 생기면 그때 씁니다.
- **`PortfolioPanel`은 아직 큽니다.** 상태와 표시가 한 컴포넌트에 있어 단위 테스트를
  붙이려면 먼저 쪼개야 합니다.
