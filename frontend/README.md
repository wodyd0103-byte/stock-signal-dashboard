# Quant Insight Frontend

Next.js, TypeScript, Tailwind CSS, Recharts 기반 투자 참고용 분석 UI입니다.

## 실행

```bash
cd frontend
npm install
npm run dev
```

기본 API 주소는 `http://127.0.0.1:8000/api`입니다. 다른 주소를 사용하려면 `.env.local`에 다음 값을 설정합니다.

```env
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api
```

## 페이지

- `/dashboard`: 종목 검색, 대표 종목 빠른 선택, 종합 분석, 가격 차트, 기술적 지표, 신호, 리스크, 가격 예측
- `/watchlist`: 관심종목 목록, 신호별 필터, 리스크 높은 종목 강조
- `/backtest`: 신호 기반 전략과 보유 전략 비교
- `/buy-signals`: 국내 대표 최대 100개, 해외 대표 최대 100개 종목의 매수 구간 신호 주기적 모니터링
- `/settings`: 데이터 제공자 설정 안내, 분석 파라미터, 투자 유의사항

## `/buy-signals` 사용법

- 시장: 전체, 국내, 해외
- 최소 신호: `WEAK BUY` 이상, `BUY` 이상, `STRONG BUY`만
- 표시 개수: 10, 20, 50, 100, 전체
- 데이터 소스: `auto`, `fallback`
- 정렬: 신호 강도, 매수 점수, 리스크 낮은 순, 등락률
- 자동 갱신: 30초, 60초, 3분, 5분

분석 중에는 기존 결과를 유지하며 갱신 상태를 표시합니다. 일부 종목 실패와 샘플 fallback 데이터 포함 여부는 화면 상단 배너에서 확인할 수 있습니다.

## 투자 유의사항

본 서비스의 분석, 예측, 매수/매도 신호는 과거 데이터와 알고리즘을 기반으로 한 참고 정보입니다. 실제 투자 결과를 보장하지 않으며, 모든 투자 판단과 책임은 사용자 본인에게 있습니다.

## 새 신호 화면 표시

대시보드의 신호 카드는 원점수와 최종 점수를 분리해서 보여줍니다. 최종 점수에는 시장국면, ML 상승확률, 상대강도, 유동성 보정이 반영됩니다. HOLD가 나온 경우에는 리스크가 높은지, 유동성이 부족한지, 시장국면 때문에 기준이 강화되었는지 등의 이유를 표시합니다.

`/buy-signals` 화면은 국내 최대 100개, 해외 최대 100개 대표 종목을 분석한 뒤 상대순위 기반으로 STRONG BUY, BUY, WEAK BUY 후보를 표시합니다. 화면에는 다음 항목이 추가로 표시됩니다.

- 시장국면 카드
- 매수 점수 상위 percentile
- 20일 상대강도 순위
- ML 5거래일 상승확률
- 유동성 점수
- 최종 매수/매도 점수
- HOLD 판단 이유
- sample fallback 여부와 실패 종목 목록

백테스트 화면에서는 절대 점수 전략, 상대순위 전략, ML 확률 전략, 시장국면 보정 전략을 비교할 수 있습니다. 모든 화면의 신호는 참고용 분석 정보이며 실제 주문 기능은 제공하지 않습니다.

## `/live-trading` 실시간 운용

새 실시간 운용 화면은 paper trading을 기본값으로 사용합니다. 사용자는 단타, 단기투자, 장기투자 모드를 각각 ON/OFF 하거나 동시에 실행할 수 있습니다.

화면에서 확인 가능한 항목:

- 현재 모드: Paper Trading / Live Trading
- 전체 상태: RUNNING / PAUSED / STOPPED
- 전체 시작, 일시정지, 중지, Emergency Stop
- 총 평가금액, 총 손익, 오늘 손익, 승률, MDD, 보유 종목 수, 활성 모드 수
- 모드별 예산, 손절/익절, 최대 보유일, 최소 신호, 리스크 제한 설정
- 실시간 포지션, 평가손익, 손절가, 익절가, 수동 청산
- 최근 주문/체결 로그, 주문 사유, 거절 사유
- 총 자산 변화 차트와 전략별 성과 비교

실거래 주문은 기본 비활성화되어 있습니다. Live Trading을 화면에서 선택하더라도 서버 `.env`의 `LIVE_TRADING_ENABLED=true`, `ENABLE_ORDER_EXECUTION=true`, broker 설정, 실거래 위험 확인, Emergency Stop 해제 조건을 모두 충족하지 않으면 실제 주문은 차단됩니다. API Key와 Secret은 프론트엔드로 전달되지 않습니다.

프론트엔드는 5초마다 `/api/live/performance`, `/api/live/positions`, `/api/live/orders`를 갱신합니다. API 오류가 발생하면 기존 데이터를 유지하고 한국어 오류 메시지를 표시합니다.
